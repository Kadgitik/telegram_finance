# Спецификация: Редизайн главной + бюджеты по категориям (A+B)

**Дата:** 2026-05-31
**Ветка:** `feature/home-dashboard-budgets`
**Статус:** утверждено к реализации

## Контекст и цель

Текущая главная (`frontend/src/pages/HomePage.jsx`) показывает баланс и список «Останні операції». Пользователь хочет переделать её по образцу скриншота: hero-блок с балансом, две карточки-метрики («Темп витрат» и «Можна витрати») и блок «ТОП КАТЕГОРІЙ» со скроллом — вместо ленты транзакций. Дополнительно — система **бюджетов по категориям**, на которой строятся эти метрики.

Тема приложения остаётся **тёмной** (Вариант 3): на главную переносится *структура* со скриншота, но в тёмных цветах, чтобы не было разнобоя с остальными экранами.

Инвестиции (группа C) — **вне этого спека**, отдельной фичей позже.

### Что уже есть в коде (переиспользуем)
- `GET /api/bootstrap` (`backend/app/routers/stats.py`) за один проход отдаёт `balance` (вкл. `expense`), `stats.categories` (суммы/проценты по категориям) и `trend` (траты по дням). Логику периода и `pay_day` уже считает `month_window_from_key`.
- Кастомные категории: `users.custom_categories`, модалка `AddCategoryModal`, эндпоинты в `routers/categories.py`.
- Фронт кеширует bootstrap в localStorage (SWR-паттерн в `HomePage`).
- Справочник категорий — `frontend/src/utils/constants.js` (`EXPENSE_CATEGORIES`, `getCategoryConfig`).

## Принятые решения (из обсуждения)

| Тема | Решение |
|---|---|
| Тема оформления | Тёмная, структура со скриншота (Вариант 3) |
| Модель «Можна витрати» | Вариант B: `total_budget = Σ лимитов по категориям`; `can_spend = total_budget − spent` |
| Бюджеты | Много категорий, вкл. кастомные «хотілки»; лимит на любую расходную категорию |
| «Темп витрат» число | `spent / days_elapsed` (средний темп за текущий месяц) |
| «Темп витрат» процент | 3d: обгон «безопасного» темпа `total_budget / days_in_period`; зелёный — в плане, красный — быстрее |
| «ТОП КАТЕГОРІЙ» | 4a: полоска = `spent/limit`, процент = «% від ліміту», краснеет при >100% |
| Накопичення в топе | Не показывать; топ только по обычным тратам |
| Где редактировать бюджеты | 5b: отдельный экран «Бюджети» (показывает все категории, вкл. с нулём трат) |
| Срок действия лимита | 5c: постоянный (задал раз → применяется каждый месяц), редактируется |
| Хранение бюджетов | Map в документе пользователя (не отдельная коллекция) |
| Данные для главной | Расширить `/bootstrap` (без новых запросов к Mongo) |
| Спарклайн | Лёгкий inline-SVG (без chart.js) |

## 1. Модель данных

Бюджеты — постоянные, хранятся как map в `users`:
```
users.budgets = { "<category_key>": <amount:number>, ... }   // только расходные категории
```
- Ключ = `key` категории (как в `EXPENSE_CATEGORIES` и `custom_categories`).
- `upsert_user` (`bot/db/queries.py`) добавляет `budgets: {}` в `$setOnInsert`.
- `delete_custom_category` дополнительно делает `$unset` соответствующего ключа из `budgets`, чтобы не копился мусор.

## 2. Бэкенд — API и формулы

### 2.1 Новый роутер `backend/app/routers/budgets.py`
- `GET /api/budgets` → `{ "budgets": {<key>: <amount>}, "total": <Σ> }` — для экрана «Бюджети».
- `PUT /api/budgets` — тело `{ "budgets": {<key>: <amount>} }`, **заменяет map целиком**. Возвращает сохранённое.
  - Валидация (`models/schemas.py` → `BudgetUpdate`): суммы `>= 0`; число категорий `<= 100`; ключи — непустые строки (с разумным лимитом длины). Отрицательные/NaN отклоняются (422).
- Аутентификация — `Depends(telegram_user_id)`, как в остальных роутерах. Rate-limit `15/minute` на `PUT`.
- Запросы к Mongo: `queries.get_user` (читает `budgets`) и новый `queries.set_budgets(db, telegram_id, budgets)`.
- Роутер подключается в `main.py`: `app.include_router(budgets.router, prefix="/api")`.

### 2.2 Расширение `GET /api/bootstrap`
Без новых обращений к Mongo: переиспользуем уже посчитанный `expense` и `trend`, плюс `user.budgets` (user-документ уже грузится). Период `[start, end_excl)` уже известен.

```
spent          = expense                                  # уже считается в bootstrap
total_budget   = sum(budgets.values())
days_in_period = (end_excl - start).days
# Сегодняшний день считается «прошедшим» (+1). Клампим в [1, days_in_period],
# поэтому для прошлых месяцев days_elapsed == days_in_period, для будущих == 1.
days_elapsed   = max(1, min(days_in_period, (now - start).days + 1))
days_left      = days_in_period - days_elapsed            # >= 0 по построению

can_spend          = total_budget - spent                 # может быть < 0 → состояние «перевищено»
daily_pace         = spent / days_elapsed
safe_pace          = (total_budget / days_in_period) if days_in_period else None
pace_vs_budget_pct = round((daily_pace / safe_pace - 1) * 100) if (safe_pace and safe_pace > 0) else None
```

Новые поля в ответе bootstrap:
```
"budgets": { ... },
"total_budget": <number>,
"days_in_period": <int>,
"days_elapsed": <int>,
"days_left": <int>,
"can_spend": <number>,
"daily_pace": <number>,
"safe_pace": <number|null>,
"pace_vs_budget_pct": <int|null>
```
Категории для топа уже есть в `stats.categories` (`name`, `amount`, `percent`, `count`) — фронт сам сматчит с `budgets` для расчёта `spent/limit`.

## 3. Фронтенд — экран «Бюджети» (`/budgets`, новый)

`frontend/src/pages/BudgetsPage.jsx`:
- Список **всех расходных категорий** = `EXPENSE_CATEGORIES` + `custom_categories` (даже с нулём трат). Для каждой: иконка (`getCategoryConfig`), название, поле ввода лимита (₴), текущее значение из `budgets`.
- Кнопка **«+ категорія»** → переиспользует `AddCategoryModal`; новая кастомная категория появляется в списке, ей задаётся лимит.
- Залипающий футер: **«Загальний бюджет: Σ ₴»** (сумма введённых лимитов в реальном времени).
- Сохранение: кнопка «Зберегти» → один `PUT /api/budgets` с полным map. После успеха инвалидируем кеш bootstrap (`homeCache_*`), чтобы главная пересчиталась.
- Тёмная тема, консистентно с приложением. Вход: иконка-кнопка на главной + пункт в `SettingsPage`.

## 4. Фронтенд — редизайн главной (`HomePage.jsx`, тёмная тема)

Сверху вниз, страница скроллится целиком:

1. **Hero-карточка** (тёмная): надпись «Залишок», крупная сумма баланса, под ней «Витрачено / Дохід», тонкий прогресс-бар (`spent` vs `total_budget`). Сохраняем `MonthSwitcher`.
2. **Ряд быстрых действий:** Дохід / Витрата / Переказ → ведут на `AddPage` (как сейчас).
3. **Две карточки рядом:**
   - «**Темп витрат**»: `daily_pace` ₴/д + спарклайн (новый `components/Sparkline.jsx`, inline-SVG по `trend.points`) + бейдж `pace_vs_budget_pct` (↗ красный если `> 0`, ↘ зелёный если `< 0`; скрыт, если `null`).
   - «**Можна витрати**»: `can_spend` ₴ + подпись «до DD Mmm · N дн» (`days_left`). Если `can_spend < 0` — красным «перевищено на X».
4. **«ТОП КАТЕГОРІЙ»** — список по убыванию `amount`: иконка, название, сумма, полоска `spent/limit` + «% від ліміту» (краснеет при `>100%`, обрезается на 100%). Тап по строке → быстрый инлайн-ввод лимита этой категории (бонус-шорткат, делает `PUT /api/budgets`). Категории **без лимита**: показываем сумму + мягкую подсказку «встанови ліміт», без полоски.
- «Борги» и «Накопичення» остаются доступны (борги — компактной строкой ниже топа либо в быстрых действиях; накопичення — через нижнюю навигацию, как сейчас).

**Маршрут:** добавить `<Route path="/budgets" .../>` в `App.jsx`.

> **Намеренное упрощение (YAGNI):** стрелка-индикатор у категории отражает статус бюджета (в плане / перебор), а не сравнение с прошлым месяцем — это избавляет от лишнего агрегата по предыдущему периоду. Историческое month-over-month сравнение можно добавить отдельно при необходимости.

## 5. Крайние случаи и обработка ошибок

- **Бюджетов нет вообще** (`total_budget == 0`): «Можна витрати» → подсказка «Встанови бюджети» (ссылка на `/budgets`); «Темп витрат» показывает ₴/д без бейджа (`pace_vs_budget_pct == null`); в топе — суммы без полосок.
- **Прошлый/будущий месяц:** `days_left == 0`, `daily_pace` считается по полному месяцу — карточки остаются корректными.
- **Перебор бюджета:** `can_spend < 0` и категория > лимита → красные состояния; полоска обрезается на 100%.
- **Удаление кастомной категории** с заданным лимитом → ключ убирается из `budgets` (см. §1).
- **Деление на ноль:** `days_elapsed` минимум 1; `safe_pace`/`pace_vs_budget_pct` → `null` при нулевом бюджете или нулевом числе дней.

## 6. Тестирование

- **Бэкенд** (pytest + mongomock, как в `backend/tests/`):
  - Формулы `can_spend`, `daily_pace`, `pace_vs_budget_pct` — вкл. нулевой бюджет, деление на ноль, прошлый месяц.

## 8. Вне scope
- Инвестиции / портфель Interactive Brokers (группа C) — отдельный спек.
- Помесячные (изменяющиеся по месяцам) лимиты — выбран постоянный режим (5c).
- Month-over-month сравнение по категориям — не делаем (см. §4).
- Перевод всего приложения на светлую тему — остаёмся в тёмной (Вариант 3).
